## 三、问题清单与修复明细

### 1.【P0，已修复】新学生开考即被强制收卷 0 分

- **现象**：考试窗口开始 40 分钟后，任何新建 attempt 的 deadline 立即为过去时间，学生一进考试就被"超时自动收卷"，0 分、负时长落库（H0004 实测复现：`duration_seconds=-166975`）。
- **根因**：`app/routers/exam.py` `start_exam` 中 deadline 误用**考试窗口开始时间**起算（种子学生数据直接写库，掩盖了此 bug）。
- **修复**：
  - deadline 改为 **开考时刻 + 40 分钟**（仍取 min 与窗口截止）；
  - `_finalize` 增加负值防护，用时上限 = min(本 attempt 时间预算，单场限时)。
- **验证**：新建学生 H0005 开考 → 剩余 2400 秒，DB 中 `deadline-started=2400秒` 精确吻合；回归后已删除 H0005。

### 2.【P1，已修复】"允许重复提交"语义矛盾

- **现象**：文案说"交卷后在考试截止前仍可恢复作答"，实际恢复按钮只看当次 attempt 的 40 分钟 deadline，过期后窗口内也无法重考。
- **修复**：`/api/exam/start` 与 `/resume` 均改为**窗口期内可恢复，并重发一个 40 分钟考试时钟**（仍受窗口截止约束，成绩以最后一次提交为准）；`exam.js`、`student.js` 的恢复按钮判断基准同步改为考试窗口截止时间（新增 `window_end` 字段）。
- **验证**：GUI 端到端——交卷页点"恢复作答"→ 新时钟 39:58、原答案保留；H0004 恢复后重新提交得 22 分、用时封顶 2400 秒。

### 3.【P1，已修复】考试"用时"三处展示不一致

- **现象**：#exam 完成态显示"—"、#/me 考试卡显示"0 分钟"、#scores 公示显示正确。
- **根因**：两个接口未返回 `duration_seconds` 原始值，前端各自兜底。
- **修复**：`exam.py` `_state_payload` 与 `student.py` overview 均返回 `duration_seconds`。
- **验证**：三处现在统一显示（示例：40 分钟）。

### 4.【P1，已修复】LLM 未配置时对话"空转"凑轮数

- **现象**：学生发消息得到"功能未开放"警告，但轮数仍 +1，空转 2 轮即可提交任务。
- **修复**：`agent.js` 轮数只统计**获得真实 AI 回复**的提问（警告回复不计）；未配置 LLM 时提交按钮给出明确引导文案。
- **验证**：H0001 此前 2 条警告提问现显示"已完成对话 0 轮"。

### 6.【功能改造，已按需求落地】评审流程调整（2026-11-08）

按需求确认的评审模式：**取消独立评委系统，智能体作品由组委会教师线下评审**（管理后台「智能体任务」模块完成 AI 检测 + 人工"合格/需修改"结论），评分链路不变（知识测试 ×50% + 智能体实操 ×50%）。

**落地内容**：

1. **评委系统下线**
   - 导航不再显示"评审工作台"（`app.js`）；
   - `#/judge` 页面改为说明卡"评委工作台未启用，本届评审由组委会教师线下开展"（`judge.js`）；

   - 后端评委相关接口保留未删（数据兼容，无入口）。

2. **智能体"答题时间"窗口统一（重要语义修正）**

   - `save / submit / retract` 在答题时间外一律拒绝，提示"答题时间已结束，智能体配置已锁定（仍可查看与体验）"；
   - 兼容规则：未启用实操考试或未配置完整起止时间 = 不限制（向后兼容既有部署与测试环境）。

3. **体验期（答题时间结束后）**
   - **不可**：修改智能体配置、保存设计、交任务、撤回、清空对话；
   - **可**：查看设计全文、**对话体验**——学生端开放对话输入（前端标注"体验模式"横幅与输入提示），供老师现场验证智能体是否符合设计要求；
